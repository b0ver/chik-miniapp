# Проверки, выпуск и восстановление

## Перед изменением

Выполнить `git status --short --branch`, работать в отдельной ветке. Проверить, что секреты исключены: `git check-ignore .env.local .local/backup.csv`. Не добавлять реальные данные участников в тесты и репозиторий.

## Проверки

Node.js 22. После изменения `dist/` выполнить:

```sh
node scripts/build.mjs
node scripts/check.mjs
node --test tests/*.test.mjs
```

Проверка проверяет синтаксис JS/Apps Script, JSON, локальные ссылки из HTML, характерный шаблон Telegram-токена и точное соответствие `docs/` свежей сборке. Это ограниченная проверка секретов, не полный аудит. Сборка проверяется во временной папке без перезаписи рабочих файлов. Для проверки интерфейса отдельно пройти изменённые сценарии в браузере и на телефоне.

## GitHub

Workflow `Quality and Pages`: PR → job `quality`; main → `quality` → публикация Pages. Workflow должен быть закоммичен и отправлен на GitHub. В Settings → Pages выбрать GitHub Actions; старый режим публикации branch/docs обходит этот workflow. Защита main должна требовать PR, успешную проверку `quality`, запрещать force push и удаление ветки, распространяться на администраторов. При единственном владельце обязательный чужой review не устанавливать.

Перед слиянием проверить изменения, зелёный CI и отсутствие секретов. После деплоя открыть публичную страницу, проверить основной сценарий, записать commit SHA и URL успешного запуска Actions в релизе. Успешный job не заменяет проверку интерфейса и внешних сервисов.

## Откат интерфейса

Найти SHA последнего рабочего релиза в успешном запуске Actions. Создать ветку из main, выполнить `git revert <SHA_плохого_коммита>` (для нескольких коммитов — от новых к старым), запустить проверки, открыть PR и слить после зелёного CI. Проверить успешную повторную публикацию и страницу без старого кеша. Не применять reset/force push. Если причина в самом workflow, исправление workflow тоже проходит PR.

## Данные демо

Состояние хранится только в браузере. Сброс демо удаляет локальные изменения; серверной резервной копии нет. Для реальных записей эта версия не предназначена. Настройки бота меняются отдельным скриптом и не откатываются вместе с HTML; перед изменением сохранить прежние публичные значения и при необходимости повторно применить их. Токен хранить только локально; утёкший токен перевыпустить через BotFather.
